# Pinterest111

Деплой - https://pinterest111-master.onrender.com/

Учебный клон Pinterest на ASP.NET Core MVC (.NET 8). Пользователи регистрируются, публикуют изображения (пины), просматривают ленту, ищут по пинам и авторам, редактируют профиль. Есть переключатель светлой/тёмной темы.

## Стек

- **ASP.NET Core MVC** (.NET 8)
- **Razor Views** (`.cshtml`)
- **Cookie-аутентификация** (`Microsoft.AspNetCore.Authentication.Cookies`)
- **Хеширование паролей** — PBKDF2 (`Rfc2898DeriveBytes`, встроено в .NET, без внешних пакетов)
- **Хранилище данных** — обычные `.txt`-файлы в `App_Data/` (`users.txt`, `pins.txt`), каждая строка — JSON-объект. Настоящей БД нет, это учебный проект
- **Bootstrap** для вёрстки

## Структура проекта

```
Pinterest111/
├── Controllers/        # Account, Register, Home, Pins, Profile, Search, Boards
├── Models/              # Pin, User, ViewModel-классы
├── Services/            # FileUserStore, FilePinStore, PasswordHasher
├── Views/               # Razor-страницы (по одной папке на контроллер) + Shared/_Layout.cshtml
├── wwwroot/
│   ├── css/             # site.css, pinterest.css (тема + стили пинов)
│   └── uploads/         # загруженные пользователями изображения
├── App_Data/            # users.txt, pins.txt — файловое "хранилище"
└── Program.cs           # настройка DI, cookie-аутентификации, middleware
```

## Функциональность

- **Регистрация / вход / выход** — cookie-аутентификация, пароли хранятся только в виде PBKDF2-хеша с солью
- **Лента (Главная)** — все пины, самые новые сверху
- **Добавление пина** — заголовок, описание, изображение (только для авторизованных)
- **Профиль пользователя** — просмотр чужого профиля и его пинов; редактирование своего (имя, юзернейм, email, био, аватар)
- **Поиск** — по названию/описанию пинов и по пользователям
- **Тёмная/светлая тема** — переключатель в шапке, выбор сохраняется в `localStorage`
- **Доски (Boards)** — заглушка, без реальной логики (`Index`/`Create` просто возвращают пустой View)

## Как запустить

```bash
cd Pinterest111
dotnet restore
dotnet run
```

По умолчанию приложение поднимется на порту из `Properties/launchSettings.json` (например, `https://localhost:7295`).

При первом запуске автоматически создаются пустые `App_Data/users.txt` и `App_Data/pins.txt`.

## Аутентификация — как это работает

- `AccountController.Login` проверяет логин/пароль через `FileUserStore` и `PasswordHasher.Verify`, затем вызывает `HttpContext.SignInAsync` с cookie-схемой
- `_Layout.cshtml` проверяет `User.Identity.IsAuthenticated`: если пользователь вошёл — в шапке показывается его юзернейм и кнопка "Выйти", если нет — "Регистрация"/"Войти"
- `[Authorize]` стоит на действиях, требующих входа (например, создание пина)

## Известные ограничения (учебный проект)

- Хранилище на `.txt`-файлах не подходит для конкурентного доступа/продакшена — только для демонстрации
- Раздел "Доски" не реализован функционально
- Нет подтверждения email, восстановления пароля, ролей/админки
